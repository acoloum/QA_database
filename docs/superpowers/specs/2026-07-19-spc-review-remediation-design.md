# SPC 程式碼檢視修正設計

**日期：** 2026-07-19

**狀態：** 已核准（使用者要求依檢視建議全數修正）

## 目標

修正近期 SPC 研究、OCAP 與快取寫入的併發競態，封閉 OCAP 輸入契約，降低研究歷程讀取成本，並修正前端責任人錯誤狀態與事件同步邏輯。

## 設計

### 交易與資料完整性

- `SPC研究` 以來源、研究類型、製程流識別鍵與品質特性作為自然唯一鍵。
- 分析計算在取得寫入鎖前完成；建立或取得研究後，鎖定研究列，再配置下一個版本號，縮短鎖定時間。
- OCAP 儲存時鎖定既有事件列，使同一事件的首次建立與後續更新序列化；資料庫唯一鍵仍作最後防線。
- SPC 預覽快取改用資料庫原生 upsert，不再以查詢後新增作為唯一防重機制。
- 資料庫衝突必須 rollback，並轉成可預期的 SPC 409 錯誤，不回傳未處理的 500。

### OCAP 契約

- 請求本文必須是 JSON 物件。
- 僅接受已定義欄位；狀態只允許 `open` 或 `closed`。
- `owner_id` 只允許真正的整數或 `null`，布林值不得視為使用者 ID。
- 6M 與重新量測欄位只接受 JSON 物件或 `null`；文字欄位只接受字串或 `null`。
- 移除前端未被後端保存的 `due_at` 契約，並以 TypeScript union 限制狀態。
- migration 增加研究自然鍵、OCAP 狀態與事件狀態約束，形成服務層與資料庫層雙重防護。

### 查詢與前端同步

- 研究詳細資料使用 eager loading，避免逐版本、逐事件 lazy-load。
- 研究歷程 API 改為分頁契約，前端提供上一頁／下一頁操作。
- OCAP 儲存成功後立即套用 mutation 回應，再以輕量事件 API 校正；不再重抓整個研究與所有樣本。
- 事件替換邏輯移到獨立工具檔，移除 React Fast Refresh 的例外抑制。
- 責任人清單載入失敗時，只標示「無法確認」，不得誤判現有責任人已不可指派。

## 錯誤處理

- 輸入錯誤使用 `SpcValidationError` 與穩定錯誤碼，HTTP 狀態為 422。
- 併發衝突使用 `SpcConflict`，HTTP 狀態為 409。
- OCAP mutation 成功但輕量校正失敗時保留已成功的本地結果，不以舊快取覆蓋。

## 驗證

- 後端加入自然鍵、狀態約束、錯型 payload、布林責任人、非法狀態、輕量事件 API、歷程分頁及快取 upsert 測試。
- 前端加入 OCAP union 契約、責任人載入失敗語意、事件輕量校正、分頁歷程與工具函式測試。
- 執行完整 `pytest`、前端 lint/build/test/audit、migration transaction dry-run 與 `git diff --check`。
