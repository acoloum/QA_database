# 出貨檢驗與巡檢 SPC 2026 現有資料適用設計

**日期：** 2026-07-18

**狀態：** 已確認

**適用手冊：** AIAG & VDA SPC Manual，第一版，2026

**範圍：** 出貨檢驗與巡檢頁面目前已保存的連續量測資料

> 本設計取代 `docs/superpowers/plans/2026-07-17-aiag-vda-spc-2026-compliance.md` 中與管制圖選型、穩定性、界限凍結及稽核版本相衝突的設計。舊計畫已完成的可沿用功能必須透過相容遷移整合，不得直接刪除既有資料。

## 1. 背景

目前系統已具備 SPC 管制圖、穩定性判定、分布評估、能力／績效指數、離群值標記及管制界限凍結等功能，但與 2026 手冊仍有下列重大落差：

1. 後端穩定性只判定 X̄ 圖，R 圖失控時仍可能宣告穩定並輸出 Cp/Cpk。
2. 出貨日期，以及巡檢日期、機台、作業員、客戶等頁面篩選條件沒有完整納入凍結基準，可能混用不同製程流。
3. 現有 `SPC管制界限` 只保存單一可覆寫結果；解除凍結會刪除資料，缺少不可變版本、核准人、資料 ID、計算版本與稽核證據。
4. 子組大小不一致時，以平均子組數取常數，造成界限偏差。
5. 常態模型未通過時仍可能保留常態結果；非正態模型候選與不適用原因不完整。
6. 部分判異規則實作與定義不符，且位置圖與變異圖沒有共同決定穩定性。
7. 目前固定以 X̄-R 為主要架構；手冊 §9.3.3 建議電腦計算優先使用 X̄-S，並先檢查 S 圖。

本次只依現有資料能證明的內容改造。現有資料無法支持的 MSA、多變量 SPC、完整抽樣設計或其他研究條件，必須明確回傳不適用，不以近似欄位推測。

## 2. 設計目標

- 出貨檢驗與巡檢共用同一個 SPC 研究引擎、資料契約及前端呈現規則。
- 位置與變異共同判定統計穩定；不穩定或模型未確認時不得宣告製程能力。
- 研究範圍完整保留頁面篩選條件、原始資料 ID、規格快照及資料雜湊。
- 正式管制界限採送審、核准、生效、停用的不可變版本流程。
- 回溯分析、持續 SPC、製程績效與製程能力在畫面及 API 上清楚區分。
- 所有計算可由保存版本重建，並有可重複執行的軟體 V&V 證據。

## 3. 非目標

第一階段不新增系統目前不存在的量測資料，也不假設下列條件已成立：

- 不以檢驗結果代替量測系統分析；沒有 MSA 資料時只顯示「尚未提供」。
- 不建立 Hotelling T²、MEWMA 等多變量模型。
- 不推導製程參數、控制計畫或抽樣 OC 曲線中不存在的欄位。
- 出貨檢驗沒有機台維度，因此不宣告機器性能 Pm/Pmk。
- 巡檢只有在單一機台、時間順序與短期受控條件均有證據時，才允許建立機器性能研究；否則只做回溯診斷。

## 4. 整體架構

出貨與巡檢服務只負責把各自資料轉成統一研究輸入，統計判定全部集中於共用研究引擎：

```text
出貨資料轉接器 ─┐
                 ├─> SPC 研究引擎 ─> 研究版本／界限版本 ─> API／報表
巡檢資料轉接器 ─┘          │
                            └─> 失控事件／OCAP／V&V 證據
```

### 4.1 資料轉接器

轉接器必須輸出：

- 來源模組、特性、完整篩選條件及正規化後的製程流鍵；
- 依時間排序的合理子組；
- 每個子組的實際 `n`、原始值、量測時間及來源資料 ID；
- 規格上下限、單邊／雙邊類型及特性重要度快照；
- 排除狀態、排除理由與操作者，不刪除原始值。

出貨與巡檢的所有有效頁面篩選都必須進入製程流鍵。只要日期、機台、作業員、客戶、材料、規格、量測項目、位置等任一有業務意義的條件不同，就不能共用正式基準。

### 4.2 SPC 研究引擎

引擎依序執行：

1. 輸入資格與資料完整性檢查；
2. 研究類型及適用性判定；
3. 時間相依模型候選判定；
4. 管制圖選型與逐組界限計算；
5. 先判定變異圖，再判定位置圖；
6. 分布模型評估；
7. 依穩定性及規格條件決定可輸出的指標；
8. 產生完整結果、證據、警告與不適用原因。

服務層是統計結果的唯一真實來源。前端與 Excel 報表不得另行重算或自行推導穩定性。

## 5. 資料模型與稽核軌跡

### 5.1 SPC 研究

保存研究來源、研究類型、完整篩選、製程流鍵、特性、MSA 狀態、抽樣說明、狀態及建立者。研究是邏輯容器，不直接覆寫計算結果。

### 5.2 SPC 研究版本

每次計算建立不可變版本，至少保存：

- 版本號、程式版本與計算方法版本；
- 資料 ID 清單及穩定排序後的資料雜湊；
- 規格與特性重要度快照；
- 時間模型候選、分布結果、圖表選型及判異規則集；
- 位置圖、變異圖、穩定性、指標及不適用原因；
- 建立時間、建立者及前一版本關聯。

### 5.3 SPC 研究樣本

保存研究版本實際採用的來源紀錄 ID、量測 ID、子組、順序、原始值、排除狀態與排除理由。排除及恢復都建立新的狀態紀錄，不修改已核准版本。

### 5.4 SPC 界限版本

正式界限採 append-only：候選、送審、已核准、生效、停用。至少保存每一實際子組大小的界限、核准理由、生效時間、停用時間、核准者及研究版本。相同完整製程流與特性同一時間只能有一個生效版本。

現有 `SPC管制界限` 資料遷移為「舊版匯入基準」，保留原始建立時間及可取得的備註。無法回填的核准證據明確標示為缺漏，不偽造人員或時間。

### 5.5 SPC 事件與 OCAP

失控事件關聯到研究版本、界限版本、圖表、規則及實際資料點。OCAP 保存重新量測、6M 原因調查、製程調整、受影響產品處置、責任人、附件及有效性確認。

### 5.6 SPC 軟體確效執行

保存黃金資料集版本、預期值、實際值、容許誤差、程式版本、執行時間及結果，讓統計方法變更可被追蹤與複驗。

## 6. 研究類型與適用性

### 6.1 回溯性製程分析

兩個頁面都可依目前篩選執行。它使用選定歷史資料計算試算界限，供診斷及建立候選基準，不代表即時 SPC，也不自動成為正式界限。

### 6.2 持續 SPC

只有完整製程流已存在生效的核准界限版本時才啟用。新觀測值只能與該版本比較，不得隨每次查詢重新置中或重算界限。製程位置或變異經確認發生實質改變時，必須停用舊版並建立新版本。

### 6.3 製程績效與能力

- Pp/Ppk：依資料與可接受分布模型呈現製程績效，不代表穩定。
- Cp/Cpk：只有時間模型確認為 A1 或 A2，且位置圖及變異圖都穩定時才可呈現及核准。
- B、C1～C4、D 或模型未確認時，不輸出 Cp/Cpk，並回傳明確原因。

## 7. 計算規則

### 7.1 時間相依模型

系統依手冊第 8 章及 ISO 22514-2 產生 A1、A2、B、C1～C4、D 的候選判定與證據：

- A1：位置固定、變異固定、瞬時與合成分布為常態；
- A2：位置固定、變異固定、瞬時與合成分布為非正態單峰；
- B：位置固定，變異系統性或隨機變化；
- C：變異固定，位置依常態隨機、非常態單峰、函數趨勢或系統性／隨機方式變化；
- D：位置及變異都可能系統性或隨機變化，合成分布為任意形狀或多峰。

自動診斷只產生「候選模型」。正式基準需由具核准權限者確認；資料不足時維持未確認，不能自動降級為 A1。

### 7.2 管制圖選型

- 合理子組 `n >= 3` 且可計算標準差時，電腦計算預設採 X̄-S。
- `n = 2`，或有經記錄的適用理由且子組通常小於 5 時，才採 X̄-R。
- 每個時間點只有一個個別值時，只有在時間順序與合理相鄰條件成立時才採 I-MR；否則回傳無適用管制圖。
- 子組大小不一致時，依每組實際 `n` 計算該點的 UCL/LCL，或使用等價的標準化圖；不得以平均 `n` 四捨五入後套用單一常數。
- S/R 圖必須包含 CL、UCL 與適用的 LCL，並以變異圖優先判定。

### 7.3 穩定性與判異規則

位置圖與變異圖分別執行已保存版本的規則集，任何一圖觸發即為不穩定。完整規則實作必須涵蓋手冊列出的八項型態，修正交替規則只辨識單一相位，以及中心線兩側規則未要求兩側都出現的問題。

同一點同一規則在重疊視窗中只保留一次違規事件，但保存觸發視窗範圍。規則集、顯著水準及啟用理由必須進入研究版本；正式基準不得因前端偏好變更而改變。

### 7.4 分布模型

分布評估採可擴充策略登錄表。第一階段只納入目前資料可驗證且已有可靠統計工具支持的候選，包括常態、適用於非負形狀特性的模型、對數常態，以及經手冊允許的轉換／非正態方法。

每個候選保存參數、適合度、接受門檻與拒絕原因。常態檢定未通過時不得沿用常態法；所有候選都不成立時，結果為「模型未確認」，而不是回退到常態。後續增加 Weibull、Gamma、Johnson、Box-Cox 或 Pearson 家族時，只需新增策略與黃金資料集，不改變 API 契約。

### 7.5 指標

- 雙邊規格依核准的分布與 G 法分位數計算 Pp/Ppk，穩定且模型適用時才以相同方法呈現 Cp/Cpk。
- 單邊規格只計算對應側指標；不虛構另一側規格。
- 無規格、樣本不足、模型未確認或數值退化時，回傳結構化不適用原因，不回傳 `0` 冒充有效指標。
- 指標輸出包含方法、估計參數、分位數、信賴資訊、樣本數、子組數及初步／正式狀態。

## 8. 核准與一致性控制

建立候選基準時，後端重新依完整製程流查詢資料並產生雜湊。送審及核准時再次比對；資料、規格、排除狀態或篩選條件變更即回傳 `409 STUDY_DATA_CHANGED`，要求建立新版本。

核准採資料庫交易及唯一條件防止並行產生兩個生效版本。停用只寫入狀態、理由與時間，不刪除界限或研究資料。

權限拆分：

- `spc.view`：查看及建立回溯分析；
- `spc.manage`：維護研究、OCAP、資料排除與送審；
- `spc.approve`：核准、停用及重新建立正式基準。

## 9. 前端設計

出貨與巡檢頁面共用 `SPCStudyPanel`，頁面現有篩選即為研究上下文。

- 頂端明確標示「回溯分析」或「持續 SPC」。
- 顯示研究類型、適用性、候選時間模型、分布證據、圖表選型、樣本充分性與計算方法。
- 同時顯示位置圖與變異圖，任何一圖失控都使整體狀態顯示不穩定。
- 原「凍結／解凍」改為建立候選、送審、核准生效、停用／重建新版。
- 核准對話框列出完整篩選、資料筆數、資料 ID／雜湊、時間範圍、子組資訊、界限及理由。
- 現場持續監控圖預設不顯示規格界限；回溯分析可切換顯示，並以不同樣式清楚區分規格界限與管制界限。
- 版本歷程可檢視每次基準、計算、核准及停用證據。
- 失控點可直接開啟 OCAP，顯示觸發規則、原始量測及後續處置。

前端只顯示後端回傳結果，不自行重算界限、穩定性或能力指標。

## 10. API 與錯誤處理

API 使用一致的研究結果契約，成功結果至少包含：研究版本、資料摘要、選型、位置圖、變異圖、穩定性、分布、指標、適用性、警告及來源證據。

不可計算不是伺服器錯誤，應以成功回應搭配穩定原因碼，例如：

- `INSUFFICIENT_SUBGROUPS`
- `INVALID_SUBGROUP_STRUCTURE`
- `TIME_MODEL_UNCONFIRMED`
- `DISTRIBUTION_UNCONFIRMED`
- `PROCESS_UNSTABLE_LOCATION`
- `PROCESS_UNSTABLE_VARIATION`
- `SPECIFICATION_MISSING`
- `MACHINE_STUDY_NOT_APPLICABLE`

資料版本衝突使用 `409`；權限不足使用 `403`；輸入欄位錯誤使用 `400`。所有錯誤回應含機器可讀代碼與繁體中文說明。

## 11. 報告與文件化

Excel／列印報告必須由保存的研究版本產生，而不是重新查詢目前資料。報告至少包含：

- 製程與特性識別、完整篩選及研究類型；
- 規格、資料蒐集條件、樣本數、子組數與各組 `n`；
- 位置圖、變異圖、分布及穩定性證據；
- 使用的方法、參數、分位數、指標及不適用理由；
- 資料雜湊、研究版本、界限版本、程式版本及核准資訊；
- OCAP 與已知資料／MSA 限制。

`docs/spc_validation.md` 必須隨新引擎更新，並移除「預設前 25 組直接凍結」等已被版本化核准流程取代的描述。

## 12. 測試與軟體 V&V

實作採測試先行，至少建立以下黃金資料集：

- A1、A2、B、C1～C4、D；
- 常態、非正態及無可接受模型；
- 單邊、雙邊及無規格；
- 固定與不等子組大小；
- 位置穩定但變異失控，以及變異穩定但位置失控；
- 各項判異規則、重疊視窗去重與數值邊界；
- Cp/Cpk、Pp/Ppk 適用與禁止情境。

確效分層：

1. 純統計單元測試，與手冊公式、SciPy 及已知資料集交叉比對；
2. 服務整合測試，確認出貨與巡檢得到相同契約；
3. API 測試，涵蓋權限、不可變歷程、資料雜湊及並行核准；
4. 前端測試，涵蓋模式、狀態、OCAP、核准與版本歷程；
5. 報告重建測試，確認舊版本輸出不受新資料影響；
6. 遷移測試，確認舊界限被保留且沒有偽造稽核欄位。

完成前執行後端全量測試、前端 lint／build／test、依賴稽核及 `git diff --check`。每次統計公式或常數變更都必須更新 V&V 執行紀錄並經程式碼審查。

## 13. 遷移與推出順序

1. 先建立新資料表、共用資料契約與黃金資料集，不改變現有畫面。
2. 實作共用研究引擎及出貨／巡檢轉接器，以功能旗標平行比對新舊結果。
3. 遷移舊界限為唯讀歷史基準，驗證資料數量與雜湊。
4. 將前端切換到共用面板與核准流程；舊凍結端點停止新增，但暫時保留唯讀查詢。
5. 報表改由研究版本重建，完成 V&V 後移除舊計算分支。

若平行比對發現新舊結果不同，必須依資料、公式、圖表選型、分布模型及穩定性逐項解釋差異；不得為維持舊數字而降低新手冊規則。

## 14. 驗收標準

- R/S 圖失控時，後端、前端及報表一致判為不穩定，且不顯示 Cp/Cpk。
- 不同日期、機台、作業員、客戶或其他有效篩選不會誤用同一正式基準。
- 不等子組大小使用逐點界限，結果可由保存版本重建。
- 常態模型被拒絕時不會回退到常態能力指標。
- 核准、停用、排除、恢復及 OCAP 都有操作者、理由、時間與不可變歷程。
- 舊界限資料完整保留；解除或停用不執行刪除。
- 出貨與巡檢使用相同統計引擎與結果契約，前端沒有第二套計算邏輯。
- 黃金資料集、API、前端、報表、遷移及全量回歸驗證全部通過。

## 15. 已確認決策

1. 第一階段只依目前已有資料實作，資料不足的手冊章節標示不適用，日後再擴充。
2. 採共用 SPC 研究引擎，不在出貨與巡檢各自維護統計公式。
