# 進階 SPC 分析設計

## 目的

依 AIAG-VDA SPC 第一版（2026）與目前已有的出貨、巡檢資料，擴充下列功能：

1. 屬性管制圖：p 圖與 np 圖。
2. 巡檢機器績效研究：Pm 與 Pmk。
3. A1、A2、B、C1 至 C4、D 時間相依分布模型診斷。
4. Box-Cox 與 Johnson SU、SB、SL 分布轉換。

本次不增加缺陷次數登錄、人工 Excel 研究資料或出貨機台來源，因此 c 圖、u 圖、出貨機器績效研究不在範圍內。

## 核准的產品邊界

- 新增獨立 `/spc/advanced`「進階 SPC 分析」頁面。
- 出貨與巡檢頁只增加摘要與進階分析連結，透過 URL query 傳遞目前篩選條件。
- 屬性管制圖只使用既有出貨／巡檢 `is_ng`，不把 NCMR 不合格數量當成缺陷次數。
- 機器績效研究只使用巡檢資料，且必須鎖定單一機台、材質、規格、量測特性與位置。
- B、C、D 診斷與分布轉換皆由系統提出候選，具權限人員填寫理由後確認或改判。
- 原始資料與既有研究版本永不覆寫。

## 架構

### 研究生命週期

所有新功能沿用既有：

`SpcStudy -> SpcStudyVersion -> 送審 -> 核准／生效界限 -> 事件／OCAP`

不建立平行的版本、權限或稽核系統。`SpcStudy` 增加 `analysis_family`：

- `variable`：既有 X-bar-S、X-bar-R、I-MR。
- `attribute`：p、np。
- `machine`：巡檢 Pm、Pmk。

研究身分與資料庫唯一鍵必須包含 `analysis_family`。生效界限的唯一範圍也必須包含研究族別，避免同一製程流的計量型、屬性型與機器研究互相取代或發生唯一鍵衝突。

研究版本保存不可變的：

- 來源篩選條件、資料雜湊與規格快照。
- 原始樣本、來源識別碼與排除紀錄。
- 圖表結果、逐點界限與失控證據。
- 分布及轉換候選、參數與配適證據。
- 時間模型候選、診斷證據、人工確認結果與理由。
- 機器研究條件、樣本資格、Pm、Pmk 與限制。
- 方法版本、程式版本、建立者、確認者及時間。

人工確認轉換或時間模型時建立後繼版本，原版本改為 `superseded`，不直接修改原本計算 JSON。

### 後端模組

- `backend/services/spc_attribute_engine.py`：p／np 圖及二項分布界限。
- `backend/services/spc_machine_performance.py`：巡檢研究資格、Pm／Pmk 與目標判定。
- `backend/services/spc_time_diagnostics.py`：位置、變異、趨勢、變點與峰態證據。
- `backend/services/spc_transformations.py`：Box-Cox、Johnson 候選、正反轉換與排序。
- `backend/services/spc_study_service.py`：協調研究生命週期，不放入各引擎公式。
- `backend/services/spc_report.py`：由不可變版本產生報表。

### 前端模組

- `src_frontend/src/pages/spc/AdvancedSpcPage.tsx`：進階分析入口。
- `src_frontend/src/components/spc/attribute/`：屬性圖條件、圖表與摘要。
- `src_frontend/src/components/spc/machine/`：機器研究資格與 Pm／Pmk。
- `src_frontend/src/components/spc/diagnostics/`：時間模型證據與確認表單。
- `src_frontend/src/components/spc/distribution/`：原始／轉換候選比較。
- 共用現有 React Query SPC hooks、Chart.js 圖表模型、權限與版本歷程元件。

## 資料流程

1. 使用者選擇研究族別、資料來源及篩選條件。
2. 來源轉接器只讀取現有出貨或巡檢資料，正規化條件並計算資料雜湊。
3. 專用引擎回傳結果或明確的不適用原因碼。
4. 使用者可預覽或建立不可變研究版本。
5. 分布轉換、時間模型與機器受控條件需要人工確認及理由。
6. 送審與核准前重建相同輸入並核對資料雜湊；不一致時回覆 `409 STUDY_DATA_CHANGED`。
7. 報表只從保存版本產生，顯示原始尺度、採用方法、統計證據及人工決定。

## 屬性管制圖

### 資料定義

- 子組間隔可選日、週或月，預設為日。
- 屬性來源使用專用轉接器：出貨不要求量測 `field`，巡檢不要求量測 `item`／`position`；研究特性固定為「不符合單位」。
- 只有能由已保存規格或公差可靠判定 `is_ng` 的紀錄才可納入。無規格、公差查無資料或判定狀態未知的紀錄排除並保存原因，不得當成合格品。
- 第 i 個子組的檢驗數為 `n_i`，`is_ng=true` 的不符合單位數為 `x_i`。
- `p_i = x_i / n_i`。
- 加權平均不符合比例 `p_bar = sum(x_i) / sum(n_i)`。

### p 圖

- 適用子組大小相同或不同的資料。
- 依手冊使用二項累積分布直接計算雙尾 `alpha=0.0027` 的逐點 LCL、UCL。
- 找不到符合尾端機率條件的 LCL 時設為 0；UCL 不得超過 1。
- 子組大小波動超過 25% 時仍依每點實際 `n_i` 計算界限，並顯示波動提示。

### np 圖

- 只有所有子組大小完全一致時適用。
- 中心線為 `n * p_bar`，逐點值為不符合單位數 `x_i`。
- 依二項累積分布直接計算整數 LCL、UCL；LCL 不得小於 0，UCL 不得大於 n。
- 子組大小不一致時回覆 `NP_REQUIRES_FIXED_SUBGROUP_SIZE`，不偷偷改用平均子組大小。

### 適用性

- 任一有效子組都必須有 `n_i > 0` 且 `0 <= x_i <= n_i`。
- 子組大小少於 50 時顯示「偵測力不足」，但可保存為初步研究。
- 全部 `x_i=0` 時只回傳摘要與 `ZERO_DEFECT_BASELINE`，不建立無法偵測惡化的管制界限。
- p／np 圖的正式失控判定至少包含超出精確二項界限。連續、趨勢等規則套用於二項 Pearson 標準化殘差，不直接以不對稱的原始比例界限估算 1s／2s 區域；核准規則集須保存並由持續監控沿用。
- p／np 圖沿用既有 OCAP，但不得把規格界限當成管制界限。

## 機器績效研究

### 來源與資格

- 只接受 `source=patrol`。
- 必須指定單一 `m_id`、材質、規格、量測項目與位置；操作者可選，但所有實際操作者均保存於證據。
- 使用巡檢 `min_val`、`max_val` 作為可追溯觀測值，不以平均值取代來源觀測。
- 至少 50 個有效觀測值才可形成正式結果；不足時只顯示初步值且不得核准。
- 使用者必須勾選研究條件受控並填寫理由；系統保存日期跨度、操作者、樣本與來源識別碼。
- 多機台、規格不一致、無有效公差、條件未確認或分布未確認時不得核准。

### 指標

- 使用 G 法的 0.135%、50%、99.865% 分位數。
- 雙側規格：`Pm = (USL - LSL) / (q99.865 - q0.135)`。
- `Pmk` 取上、下側偏移指標中較小者；單側規格只計算相應側。
- 常態分布時等同 6s 公式。
- 依特性重要度顯示目標值：關鍵 2.33／2.00、主要 2.00／1.67、次要 1.67／1.33、其他 1.00／1.00；樣本少於 50 不以目標達成宣告正式合格。

## 時間模型診斷

### 診斷證據

- 位置圖與變異圖是否穩定。
- 位置序列的線性／單調趨勢及顯著性。
- 單一或多重平均值變點與分段平均。
- 組內或子組間變異是否改變。
- 標準化組內殘差的瞬時分布。
- 合成分布的常態性、單峰或多峰證據。
- 可重現的統計量、門檻、原因碼及資料索引。

正式診斷至少需要 25 個有效子組；不足時只回傳初步候選且不得確認。檢定顯著水準固定為 `alpha=0.05`，同一診斷批次的多重比較使用 Holm 校正。位置趨勢使用 Kendall tau 與 Theil-Sen 斜率；平均值變點以最小分段 5 個子組的遞迴候選切分配合 Welch 檢定；變異改變使用時間分段 Levene 檢定並結合變異圖失控證據。合成分布單峰／多峰以固定網格 KDE 與顯著峰值條件判斷，所有門檻及偵測到的索引均寫入結果。

### 分類

- A1：位置固定、變異固定、結果為常態分布。
- A2：位置固定、變異固定、結果為非常態單峰分布。
- B：位置固定，變異有系統性或隨機改變。
- C1：變異固定、位置隨機改變，合成分布仍為常態。
- C2：變異固定、位置隨機改變，合成分布為非常態單峰。
- C3：變異固定、位置依函數系統性改變，例如刀具磨耗趨勢。
- C4：變異固定、位置同時有系統性與隨機變化，例如批次階躍。
- D：位置與變異都改變，合成分布可為任意形狀或多峰。

系統提出 `candidate`、`candidate_options`、證據與原因碼。具 `spc.approve` 權限者可確認或改判，但模型必須在 A1、A2、B、C1、C2、C3、C4、D 中且理由不可空白。B、C、D 不回報穩定製程 Cp／Cpk。

分類優先序為 D、B、C3、C4、C1／C2、A1／A2：位置與變異同時改變先判 D；只有變異改變判 B；變異固定時，顯著單調趨勢判 C3，顯著階躍或多重變點判 C4，沒有系統型態但位置不固定時依合成分布常態性判 C1 或 C2；位置與變異都固定時依原始瞬時分布判 A1 或 A2。人工改判不會刪除系統候選及原始證據。

## Box-Cox 與 Johnson 轉換

### 候選

1. 先評估原始資料；原始分布通過時不主動推薦轉換。
2. Box-Cox 只接受全部大於零的資料。
3. Johnson 評估 SU、SB、SL；SL 以相應對數常態參數表示。
4. Johnson 以配適分布 CDF 映射至標準常態；反轉換以配適分布 PPF 還原。Box-Cox 保存 lambda 與必要位移資訊。
5. 每個候選保存轉換參數、常態性檢定、尾部分位數有效性、數值穩定性及排序分數。

### 選擇與保存

- 只有通過受控門檻的候選可推薦，沒有候選通過時回覆 `DISTRIBUTION_UNCONFIRMED`。
- 通過條件為轉換後 Anderson-Darling `p >= 0.05`、0.135%／99.865% 分位數有限、轉換單調且正反轉換相對誤差不超過 `1e-9`。候選依 p 值由高至低、AD 統計量由低至高排序。
- 系統不自動採用；具 `spc.approve` 權限者填理由確認。
- 確認後建立後繼研究版本，保存採用的轉換和參數。
- 原始樣本永不修改。管制圖可在轉換尺度運算，但 UI 與報表必須清楚標示尺度。
- 規格外風險、分位數及報表結果透過反轉換回到原始尺度。
- 時間模型仍依原始尺度的瞬時與合成分布分類；採用轉換不會把原本的 A2 人為改標成 A1。

## API 與權限

延伸既有 `/api/spc-studies` 契約：

- 分析與建立版本請求增加 `analysis_family`，以及屬性子組間隔或機器條件確認資訊。
- 新增確認分布轉換操作。
- 延伸時間模型確認操作，使其可確認或有理由地改判 B、C1 至 C4、D。
- 版本詳情統一回傳族別、圖表、機器績效、時間模型診斷與轉換證據。
- 版本 Excel 報表支援三種研究族別；巡檢報表不得再由即時預覽直接產生。

權限：

- `spc.view`：查看與預覽。
- `spc.manage`：建立研究、確認機器研究條件及送審。
- `spc.approve`：確認轉換、確認或改判時間模型、核准或退回。

所有狀態轉換、確認與改判都寫入 AuditLog，保存舊值、新值、操作者、時間與理由。

## UI

`/spc/advanced` 提供四個工作區：

1. 屬性管制圖：來源、日／週／月、p／np 圖、逐點界限與事件。
2. 機器績效：巡檢條件、樣本資格、Pm／Pmk、目標及限制。
3. 時間模型診斷：候選、趨勢、變點、變異、分布證據與確認表單。
4. 分布轉換：原始、Box-Cox、Johnson 候選比較與確認表單。

頁面必須處理無權限、資料不足、來源變更、統計不適用與 API 失敗。圖表預設不疊加規格界限；使用者啟用分析模式時才可顯示，且視覺上必須與管制界限區隔。

## Migration 與相容性

- 新增 `SPC研究.analysis_family` 非空欄位，既有研究回填 `variable`。
- 調整研究與生效界限唯一約束，使 `analysis_family` 成為唯一身分的一部分。
- 方法版本與輸入契約版本升為 `2026.2`。
- 舊 `2026.1` 版本不重算、不修改，仍可查看及匯出。
- migration 必須先在 PostgreSQL 交易中 dry-run，再正式套用並核對 schema。
- 套用前確認每日備份存在且可用。

## 錯誤處理

至少提供下列穩定原因碼：

- `ATTRIBUTE_NO_VALID_SUBGROUPS`
- `ZERO_DEFECT_BASELINE`
- `NP_REQUIRES_FIXED_SUBGROUP_SIZE`
- `MACHINE_SOURCE_UNSUPPORTED`
- `MACHINE_STREAM_NOT_FIXED`
- `MACHINE_SAMPLE_INSUFFICIENT`
- `MACHINE_CONDITIONS_UNCONFIRMED`
- `SPECIFICATION_UNCONFIRMED`
- `BOXCOX_POSITIVE_VALUES_REQUIRED`
- `TRANSFORMATION_UNCONFIRMED`
- `TIME_MODEL_OVERRIDE_INVALID`
- `REASON_REQUIRED`
- `STUDY_DATA_CHANGED`

錯誤回應包含繁體中文訊息與結構化 details；不使用例外堆疊作為 API 訊息。
